This bench's single-point number is sufficient to validate the extraction mechanics, not to claim a compression-verified IIP3.
- **Note**: dBm convention: Pin_dBm uses the standard available-power formula for a Thevenin source with series Z0 (V_peak^2/(8*Z0)); Pfund_dBm/Pim3_dBm/lo_rf_leak_dbm use V_peak^2/(2*Z0) at the (unterminated) output/RF-port node, i.e. Z0=50 ohm is a REPORTING reference only, not an assertion that the output is impedance-matched. Both dBc-difference terms (conversion_gain_db, the IIP3 extrapolation's Pfund-Pim3) are insensitive to this approximation since both sides use the identical conversion.

This is a real ngspice/general-SPICE tooling gap, not a klayout-tools gap -- klayout-tools does no simulation and is not invoked anywhere in this bench.

This placeholder is SINGLE-ENDED -- there is no differential pair for a mismatch corner to unbalance -- so that guidance does not map onto this circuit; lo_rf_leak_dbm here is swept only against the plain (non-mismatch) hbt corner set.
